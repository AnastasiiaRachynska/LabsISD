Implemented behavior:
- Pushes supported OpenAPI resource changes with authenticated HTTP transport,
  a persisted retry-stable Idempotency-Key, and create/update/delete shapes.
- Removes only acknowledged queue records; retains failed/unacknowledged
  changes and coalesces repeated local writes before synchronization.
- Persists remote/local resource identity and server versions for subsequent
  updates and deletions.
- Applies pulled resources and tombstones within a SQLite transaction and
  advances the opaque cursor only after all local writes succeed.
- Persists local/server conflict versions and queues a selected resolution
  against the server's latest version.
- Records sync completion and failure events through the diagnostic audit log.
- Wires Entry, Book, Chapter, Tag, and relationship writes into the outbox.
- App.tsx restores secure credentials and a configurable API URL, supports
  registration/login/logout, provides manual Sync Now, and displays persisted
  unresolved conflict counts without conflict-resolution controls.

Constraints and limitations:
- Do not modify mock-api or mock-api-tests. In addition to injected transport
  tests, app sync is verified against the local WNT-11 SQLite backend.
- No automatic connectivity trigger or conflict-resolution controls are
  included. Sync is user-initiated.
- The authenticated round-trip is verified against the local WNT-11 SQLite
  backend in tests, but deployment, HTTPS termination, physical-device network
  connectivity, and a production hosted service remain unverified.
- No documentation files are added; ticket records are kept in logs/.

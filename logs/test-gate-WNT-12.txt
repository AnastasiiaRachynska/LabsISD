deletions, and conflict resolution.

Gate definition:
- Consumer-contract suite: tests/wnt-12-synchronization.test.js.
- Traceability tests map each functional synchronization requirement and the
  related offline/durability acceptance criteria to WNT-12.
- Push scenarios validate OpenAPI create/update/delete change shapes,
  Idempotency-Key use, per-change acknowledgment, retention of failed or
  unacknowledged work, network failure behavior, and preservation of both
  versions on a version conflict.
- Pull scenarios validate the opaque saved cursor, create/update/delete
  application (including deletion tombstones), atomic cursor advancement only
  after local application, malformed response rejection, and expired-cursor
  behavior.
- Conflict scenarios validate preservation and selection of local/server
  versions and queueing a subsequent update against the current server version.
- The tests specify a client service contract: `createSynchronizationService`
  with pendingChanges, syncMetadata, syncApi, localStore, conflicts, and ID
  dependencies. `localStore.withTransactionAsync` must make remote application
  and cursor persistence atomic.
- Existing real-SQLite persistence evidence is in
  tests/sqlite-persistence.integration.test.js; platform offline/reopen
  verification remains distinct from host unit tests.
- Commands:
  npm test -- --runInBand tests\wnt-12-synchronization.test.js
  npm test -- --runInBand --coverage
